● Found the root cause. Here's the diagnosis:

  ---
  Root cause: showInlineDiff immediately writes to Monaco, triggering an 
  auto-reparse that applies changes before the user accepts

  The flow when NOT on the AI tab:

  1. AI finishes → showInlineDiff(oldText, newText) is called
  2. Line 2558: editor.setValue(newText) — writes the new URDF directly to 
  Monaco (this is supposed to be a "preview")
  3. monacoModels['robot.urdf'].onDidChangeContent fires (line 748)
  4. 500ms debounce → reparseURDF() runs → 3D view updates to the new robot 
  automatically
  5. Floating diff bar appears over the Monaco editor with Accept/Dismiss

  At this point the changes are already live in both the Monaco editor and the 
  3D view. The user on the 3D tab sees the robot change shape/structure.

  Then when the user accepts (via the floating bar OR by switching to chat to
  click "Apply Changes"):
  - acceptInlineDiff() calls reparseURDF() again
  - But the 3D view already shows the new robot — nothing visually changes
  - The user perceives this as "Accept did nothing" / "changes didn't apply"

  And crucially — because pendingOldText is still set and Dismiss is still
  available, if the user clicks Dismiss (thinking they're just closing the diff
  bar, since the 3D already updated), dismissInlineDiff() calls
  editor.setValue(pendingOldText) which reverts Monaco to the old URDF and
  triggers another reparse that reverts the 3D view back. From the user's view:
  they accepted, nothing happened, then dismissed, and suddenly the robot
  reverted.

  Secondary issue: The "Apply Changes" button lives inside #viewport-chat which
  has display: none when on the 3D tab. The floating diff bar is the only accept
   path while on 3D — but if Monaco is hidden (viewport fullscreen F or focus
  mode Shift+F), the bar is positioned off-screen because
  getBoundingClientRect() returns zeros:
  // line 2586-2588
  const rect = editorEl.getBoundingClientRect()  // all zeros when Monaco hidden
  bar.style.right = (window.innerWidth - rect.right + 20) + 'px'  // = 
  window.innerWidth + 20px → off-screen left

  Summary of issues:
  1. showInlineDiff uses editor.setValue(newText) as "preview" but this fires
  the existing onDidChangeContent listener, which does a full 3D reparse —
  changes apply automatically before any user action
  2. Accept then looks like a no-op (3D already matches), making users think it
  didn't work, then they may Dismiss which actually reverts everything
  3. Floating bar goes off-screen when the editor panel is hidden

  The fix would need to either: suppress the debounce reparse while a diff is
  pending (pendingOldText !== null), or stage the new URDF separately without
  writing it to Monaco until explicit accept.
